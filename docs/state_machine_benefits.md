# مزایای استفاده از State Machine در مدل خرید

## تغییرات اعمال شده
- جایگزینی فیلدهای بولین متعدد با یک فیلد وضعیت (`state`)
- ایجاد متدهای مشخص برای انتقال بین وضعیت‌ها
- ثبت تاریخچه تغییرات وضعیت در مدل `PurchaseStateChange`
- سازگاری با کد قبلی برای انتقال تدریجی

## مزایای رویکرد جدید
1. **کاهش پیچیدگی**: به جای ۲۰+ فیلد بولین، فقط یک فیلد `state` داریم
2. **افزایش خوانایی کد**: درک جریان خرید بسیار ساده‌تر شده است
3. **اعتبارسنجی بهتر**: انتقال بین وضعیت‌ها فقط در صورت مجاز بودن انجام می‌شود
4. **تاریخچه بهتر**: ثبت دقیق تغییرات وضعیت به همراه زمان، کاربر و توضیحات
5. **سادگی توسعه**: افزودن وضعیت‌های جدید بسیار ساده‌تر است
6. **کاهش خطا**: منطق تغییر وضعیت در یک جا متمرکز شده است
7. **قابلیت گزارش‌گیری بهتر**: آمار دقیق‌تر از زمان صرف شده در هر مرحله

## نحوه استفاده از مدل جدید
برای تغییر وضعیت خرید، به جای استفاده از متدهای `check_is_*` قدیمی، از متدهای جدید استفاده کنید:

```python
# روش قدیمی
purchase.check_is_bazaaragahed(user_role='logistics_manager')

# روش جدید
purchase.confirm_bazaargah(user)
```

متدهای جدید:
- `confirm_bazaargah(user)`: تایید خرید در بازارگاه
- `verify_payment(user)`: تایید پرداخت
- `register_allocation(user)`: ثبت تخصیص
- `approve_allocation(user)`: تایید تخصیص
- `settle_with_vendor(user)`: تسویه با واردکننده
- `send_address_to_vendor(user)`: ارسال آدرس به واردکننده
- `send_to_shipping(user)`: ارسال به باربری
- `issue_barnameh(user)`: صدور بارنامه
- `mark_as_delivered(user)`: تحویل به مشتری
- `approve_difference(user)`: تایید مبلغ اختلاف
- `deposit_shortage(user)`: واریز کسری
- `deposit_surplus(user)`: واریز سرک
- `submit_receipt(user)`: ثبت رسید
- `issue_invoice(user)`: صدور فاکتور
- `approve_by_sales(user)`: تایید واحد فروش
- `approve_by_logistics(user)`: تایید واحد لجستیک
- `approve_by_financial(user)`: تایید واحد مالی
- `mark_as_urgent(user)`: پیگیری فوری
- `cancel_purchase(user)`: لغو خرید
- `archive_purchase(user)`: آرشیو خرید

## نکات پیاده‌سازی
1. تا زمانی که کد کاملاً به روش جدید منتقل شود، فیلدهای بولین قدیمی نیز برای سازگاری با کد موجود حفظ شده‌اند.
2. در متد `_sync_states_with_booleans` همگام‌سازی وضعیت جدید با فیلدهای بولین قدیمی انجام می‌شود.
3. در دراز مدت، باید تمام فیلدهای بولین قدیمی و متدهای `check_is_*` را حذف کرد.
